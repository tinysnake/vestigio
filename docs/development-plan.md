# Vestigio 开发计划

目标是构建通用的轻量分层记忆系统，第一版接入 pi-agent。主 Agent 在需要时主动查询记忆，系统保留可核验的历史来源，并控制整理历史和读取结果的成本。

本文是待讨论的实施计划。当前只交付计划与调研记录，不启动功能实现。原始需求见 [requirements-2026-11-17.md](requirements-2026-11-17.md)，最新修订见 [requirements-update-2026-11-17.md](requirements-update-2026-11-17.md)。两者不一致时以最新修订为准。已验证事实与未验证假设见 [research-2026-11-17.md](research-2026-11-17.md)。

## 1. 先锁定系统边界

保留以下需求，以最新修订为准。

- 短期层由热点关键词、别名、关联记忆 ID 和派生导航短摘要组成，是中期记忆的索引视图。
- 不向 system prompt 注入热点词表，Session 初始化也不向模型发送词表。
- 每轮真实用户输入由宿主程序在本地匹配。命中后只在本次用户输入末尾附加相关短摘要和长摘要读取方式，并执行去重。
- 中期摘要为 500 至 1000 字，回答“我们之前讨论了什么，得出了什么结论？”。Agent 先总结 Obelisk 证据，再基于中期摘要二次生成不超过 200 字符的短摘要。
- 短摘要回答“这条记忆包含哪些信息，什么时候值得读取？”。它不承担完整事实回答。
- 主 Agent 主动查询。每轮关键词匹配不调用 LLM，也不搜索整段历史。
- 基础搜索依次覆盖 Active、Archived、Obelisk。Archived 不参与 Active Top 5 排名。候选允许扩展到 Top 10。
- 中期摘要保留证据来源。历史内容不升级为指令。
- 复杂检索有时间、模型调用、结果字节及输出 Token 预算。
- LLM 下探 Obelisk 并取得有效历史证据后，必须生成中期摘要，同一份内容返回主 Agent 并持久化，再派生短摘要、评估入热点池。不另设可选保留价值关卡。无结果或证据不足不编造摘要。
- 中期记忆记录命中次数、访问次数和上次访问时间，用于排序与归档。命中不等于长摘要访问。第一版不强制主 Agent 额外反馈“实际采用”。
- 归档不物理删除摘要。

第一版暂缓知识图谱、向量数据库、逐轮语义召回、全量实时总结、复杂自动合并、自动物理删除、跨设备同步和通用插件框架。先提供一个 pi 适配器和一个 Obelisk 来源适配器。

## 2. 建议的技术形态

建议使用 TypeScript、SQLite 和 pi extension。Node 运行时与 SQLite 驱动在 PR-01 根据 pi 的实际加载方式确定，并固定支持版本。当前机器的 Node 版本不能代表发布支持范围。

比较了两种模块形态。

| 形态 | 状态和调用关系 | 优点 | 第一版成本 |
| --- | --- | --- | --- |
| 独立核心包与薄适配器 | 核心包拥有记忆状态、检索及任务逻辑。pi extension 和 CLI 调用同一核心接口 | 本地调用直接，便于回放测试，第二个 agent 可复用 | 多个 pi 进程需要正确处理 SQLite 短事务、忙重试和幂等 |
| 常驻本地服务与客户端 | 常驻服务拥有存储和任务，pi 通过 IPC 调用 | 后台任务与多客户端管理集中 | 增加进程发现、服务升级、恢复、IPC 及安装维护 |

建议先采用独立核心包。CLI 用于导入、诊断、手动归档和执行维护，不承担主 Agent 的多轮工具编排。只有当实测显示持续后台任务或多客户端协调确有需要时，再增加常驻服务。核心数据结构不依赖 pi Session 对象或 Obelisk 表结构。

第一版的边界只保留四处。

- `MemoryCore` 提供搜索、读取、复杂检索、两阶段摘要提炼及访问统计。
- `HistorySource` 提供能力探测、候选搜索和有界证据读取。
- `ModelClient` 提供带 deadline、取消信号和费用记录的结构化模型请求。
- pi extension 负责生命周期、工具名称映射和提示注入。

Obelisk 通过受控 CLI 查询脚本访问，用户文字以数据形式编码。核心不接收模型提供的任意 JavaScript 或 SQL。第一版不调用 Obelisk 的记忆写入接口，也不向其原始历史库写入 Vestigio 摘要。

Obelisk CLI 的查询入口会尝试刷新索引，不能把“只读查询 API”误解为整个调用绝对没有索引维护行为。PR-03 必须验证刷新、锁等待和失败时的处理方式。

## 3. 先定义数据形状

下表是逻辑字段，不是最终 SQL DDL。PR-01 固定必填字段、边界校验及契约用例后再实施。

| 对象 | 关键字段 | 约束 |
| --- | --- | --- |
| Memory | `id`、`revision`、`uri`、`scope`、`project_id`、`title`、`navigation`、`navigation_source_revision`、`body`、`keywords`、`aliases`、`state`、`pinned`、`hit_count`、`access_count`、`last_access_at`、`created_at`、`updated_at` | `body` 为中期摘要，`navigation` 是基于该 revision 的二次短摘要。ID 与 URI 不因标题或归档改变。命中和访问分开 |
| SourceRef | `source_instance_id`、`provider`、`session_id`、`message_id`、`parent_id`、`timestamp`、`project_id`、`locator`、`excerpt_hash` | 允许一个摘要关联多处证据。保留 provider 原生标识及 Obelisk 标识，验证重建后是否稳定 |
| EvidenceExcerpt | `source_ref`、`text`、`visibility`、`truncated`、`ancestry_mode` | 截断和失效分支必须可见。普通时间邻居不代表同一因果分支 |
| SearchCard | `memory_id`、`uri`、`title`、`navigation`、`layer`、`matched_terms` | 候选不是答案。排序分数不代表正确概率 |
| RetrievalResult | `status`、`cards`、`answer`、`memory_summary`、`memory_uri`、`revision`、`persistence_status`、`navigation_status`、`evidence`、`missing`、`conflicts`、`next_action`、`continuation_id`、`budget_used` | Obelisk 成功路径返回已生成的中期摘要及其保存状态。查询结果、持久化结果和短摘要任务状态分开，不以 resolved 表示全部完成 |
| UsageEvent | `event_id`、`session_id`、`request_id`、`memory_id`、`kind`、`channel`、`at` | `kind` 区分 hit 与 access，channel 保留热点匹配、搜索或长摘要读取来源。重试不重复计数 |
| HotspotSnapshot | `version`、`scope`、`project_id`、`keywords`、`aliases`、`memory_ids`、`navigation`、`created_at`、`content_hash` | 宿主本地索引，不整体注入提示词，只包含短摘要已就绪的活跃记忆 |
| ProjectActivity | `project_id`、`activity_seq`、`last_input_at` | 同一项目每次接受真实用户输入推进一次逻辑时钟，重复事件不推进，闲置不推进 |
| HotspotMembership | `project_id`、`memory_id`、`admitted_seq`、`last_hit_seq`、`last_access_seq`、`recent_hit_weight`、`recent_access_weight` | 项目内的入池与近期热度记录。退出热点不改变 Memory 的 Active 或 Archived 状态 |
| InjectionReceipt | `session_id`、`branch_ref`、`input_id`、`memory_id`、`revision`、`committed_at` | 记录真正交付的注入块，别名按记忆 ID 去重。未交付不能标记已注入 |
| RetrievalJob | `id`、`idempotency_key`、`state`、`deadline`、`budget`、`checkpoint`、`lease_expires_at` | 分别记录中期摘要、短期摘要阶段结果，第二阶段失败不重复第一阶段 |

记忆 URI 建议采用 `memory://<store-id>/<memory-id>`，来源另有稳定定位字段。物理路径不作为项目的永久主键。第一版使用本机项目 ID 与路径映射；跨设备只预留来源实例命名空间。

不要在初版引入复杂版本合并系统。保留单调递增的 revision、内容 hash、来源及明确的 `supersedes` 关系即可。出现不确定冲突时保存独立条目，返回冲突状态。后来的记录只有在项目归属、内容含义与明确覆盖关系支持时才替代旧结论，不能机械地选最新时间戳。

至少区分项目记忆与显式全局记忆。作用域已定为项目级：默认检索当前项目，跨项目或全局偏好必须显式扩大范围，不因别的项目曾用过就自动进入结果。

## 4. 检索和提示策略

### 4.1 热点层

热点池通常很小，第一版优先使用规范化词与显式别名匹配。统一空白、大小写和全半角，避免把英文短标识匹配进无关长词。中文命中仅是检索提醒，不能直接判定语义相关。

FTS5 提供索引，BM25 提供排序，两者可以配合。不要把整条自然语言消息直接当作 FTS5 查询。中期搜索的中文分词、连续文本和短词问题见调研记录。

初始化只在宿主本地加载热点索引，不向 system prompt 或开场消息发送词表。每轮匹配后，在本次用户输入末尾附加短摘要与长摘要读取方式。没有命中则不附加。旧方案中按 20% 至 30% 词表变化追加整个版本的设计撤销，本地索引更新本身不生成提示词。

注入块包含记忆 ID、短摘要、稳定 URI 和实际注册工具的读取语法。中期正文仍由 Agent 按需读取。一个词关联多条歧义记忆时分列显示，并受单条输入总字节或 Token 预算约束。

去重先采用以下解释，属于待试用确认的产品默认值。

- 同一输入多个词或别名指向同一记忆，只附加一次。
- 同一 Session 已注入的记忆不因后续再次命中而重复附加。默认按记忆 ID 去重，修订更新也不自动再次注入。
- 新 Session 使用新记录。继续 Session 与重启进程恢复已有记录。
- 分叉继承当前分支实际包含的注入记录，回退不受被放弃分支的记录影响。
- 压缩不清空去重记录，不默认触发重新注入。更新或压缩后的再次提醒需要另行确定规则。
- 匹配回调不等于交付成功。只有最终输入已提交后，才记录注入完成。预算未容纳或发送失败的块不应被永久抑制。

短摘要上限包含 200，不要求凑满。URI、读取语法和元数据不计入短摘要自身长度，但计入整体注入预算。敏感字段不进入关键词、短摘要或日志。

### 4.1.1 热点更替建议

使用者明确不希望因固定 48 小时等期限，使闲置项目的热点整体过期。以下方案将这一约束落到项目、时间与容量三个维度。具体排名公式和容量尚未选定，需要回放验证。

首先区分三件事。

| 操作 | 含义 | 保留什么 |
| --- | --- | --- |
| 退出热点池 | 不再参与当前项目逐轮自动匹配 | 中期摘要、派生短摘要、URI、来源与统计均保留，仍可主动搜索 |
| 中期归档 | 不参与默认 Active Top 5 | 归档层仍可查，不物理删除 |
| 清除内存中的项目缓存 | 释放进程资源 | 磁盘热点快照保留，项目恢复时重新加载 |

热点资格是独立于 Active 和 Archived 的索引成员关系。不要把退出热点池直接实现成中期归档，也不应删除已经付费生成的短摘要。

**按项目保存热点池。** 项目 A 闲置、项目 B 持续使用时，B 的活动不降低 A 的本地热点排名。回到 A 时先恢复持久化快照，不能先按自然日清空再冷启动。全局记忆若启用，使用独立配额，不让其他项目挤占当前项目的基本空间。

**容量限定规模，时间调整优先级。** 同时配置每项目热点记忆条数、别名总数和索引字节上限。一个关键词关联多条记忆时按记忆条目分别占用容量。每轮能追加多少内容另受输入预算限制，不能把本地池容量等同于提示词 Token 预算。

未达到容量上限时，不仅因时间流逝移除仍有效的热点。达到上限且有值得进入的新候选时，才比较留存价值，替换较弱条目。明确失效、被撤销或已归档的条目及时退出；涉及配置有效期时单独记录事实有效性，不能以“仍在热点”证明配置有效。

**项目活跃轮次作为初版的时间信号。** 每个项目对真实用户输入维护递增的 activity_seq。距最近命中、最近读取经历了多少项目输入，表示该记忆在多少次使用机会中没有被需要。没有输入就不推进；不能从后台运行时间或最后一轮到现在的墙钟间隔推算活跃时长。last_access_at 仍保留真实时间用于展示和维护，但自然日跨度不作为热点硬失效条件。

排序信号先用最近成功读取、近期读取频率、近期匹配及新条目试用机会。成功读取的权重应高于单纯匹配，搜索候选曝光不自动提升热点。累计 hit_count 和 access_count 保留用于审计，近期热度按项目活跃轮次衰减，不能用永久累计值让早期热点一直占位。权重与衰减速度通过回放决定。

新生成的完整记忆、明确固定的记忆、通过主动搜索找到并成功读取的记忆可成为入池候选。普通未入池记忆不会被热点匹配命中，因此必须保留这些独立的晋升入口，不能形成“必须先命中才能入池”的循环。Archived 记忆先通过独立恢复流程回到 Active，再评估入池。

新候选只在明显优于池中较弱条目时替换，避免轻微分数变化反复换位。给新条目有限的活跃轮次试用机会，固定项和试用项也占用配额。固定项用满容量时报告容量冲突并暂停普通晋升，不能静默突破上限或淘汰固定项。具体替换余量和试用轮数待实验。

| 场景 | 建议行为 |
| --- | --- |
| 项目放置几天后回来 | 恢复原热点池，不因闲置自动失效 |
| 持续开发但没有新增热点候选 | 原热点逐渐降权，容量未受压时无需清空 |
| 持续产生并读取新的记忆，热点池已满 | 按近期价值渐进替换弱条目，保留摘要与来源 |
| 旧热点退出后再次被主动搜索并读取 | 评估重新入池，不重新生成已有短摘要 |
| 只是打开项目或后台执行维护 | 不推进活跃轮次，不制造命中或访问 |

热点池移出再入不能重置 Session 的注入去重记录。磁盘占用问题由独立存储维护处理，不能借本地缓存回收删除闲置项目的热点快照。

### 4.2 中期与原始历史

`memory.search` 默认只返回 Active Top 5 导航卡片。无候选时自动查询 Archived。有候选但语义不相关时，主 Agent 可用返回的下一步操作继续查询 Archived，不能用 BM25 分数自动宣判内容已经足够。

归档层也不足时，使用显式的历史层查询或 `memory.resolve`。不要让一次普通 `memory.search` 隐式启动模型和多轮历史扫描。

Active 与 Archived 建议使用独立 FTS 索引。先按作用域和状态限定候选，再排序、取 Top 5。不能先取全库 Top 5 后过滤。生命周期迁移与索引更新在同一个事务内完成。

历史层的命中不能只按因果父路径读回。实测里用户提问本身常是它自己最好的词法命中，答案在它的子消息里；只读父路径等于把问题原样交回给模型。所以命中后做一次有界窗口读取：先取因果父路径（证据链），最佳命中角色是 `user` 时再补一小段向前的时间邻域（默认 2 条），把回复带入证据。两次读取共用一个字节上限。

原始历史的词法能力有一条已测边界：Obelisk 0.3.2 把中文按标点与空白切成整段词元，不做词或子词切分。隔离 fixture 上搜 `回滚`、`默认端口`、`部署脚本的默认端口` 均为 0 命中，只有整句 `回滚要注意什么` 命中 1 条。也就是说中文问题基本搜不到原始历史，只有与历史里某个标点段完全一致时才命中。记忆库用中文单字与二元组索引，不受此限。PR-09 必须分别报告“记忆层召回”和“原始历史召回”，不能合并成一个数字。

中期索引包含标题、关键词、别名、导航及正文。当前问题相关性先决定候选，命中次数、访问次数与上次访问时间再提供有界辅助权重。不能让长期热门但不相关的条目压过相关证据。事件保留热点匹配和搜索来源，避免曝光产生无限自我强化。字段和统计权重通过固定样本评估。

热点精确命中与 BM25 结果可在统一候选结构中合并。FTS 分数只用于同一索引的排序，不直接比较不同层的分数。

### 4.3 工具契约

以下是逻辑 API 名称。pi 注册工具时采用 `memory_search` 等兼容名称。

| 操作 | 输入重点 | 输出及副作用 |
| --- | --- | --- |
| `memory.search` | query、scope、layer、limit、时间范围 | 导航候选、来源层和下一步动作。零额外 LLM 调用，记录返回候选的命中事件 |
| `memory.read` | URI、可选 revision | 完整摘要、来源、冲突与过时标记。成功交付时增加访问次数并更新上次访问时间 |
| `memory.resolve` | question、scope、budget、可选 continuation | 有预算的分层检索。下探 Obelisk 取得有效证据后，必须生成、保存并返回同一份中期摘要，触发短摘要更新，状态分别报告 |
| `memory.save` | 用户明确要求保存的内容或已检索证据引用 | 显式写入入口。Obelisk 成功检索路径内部自动写入，不再要求主 Agent 单独调用本工具 |

第一版的 `resolved` 表示执行器认为证据足以支持问题，不是事实真伪保证。必须同时返回证据与尚存限制。基础搜索只找到导航候选时不得标为已解决。

同一问题最多两次主 Agent 请求，热路径约 30 秒，均作为初始可配置预算。Obelisk 需要先刷新增量索引时属于冷检索，允许超过 30 秒，上限 120 秒，并如实报告各阶段耗时；冷检索不能因此被截断成不完整结果。执行器还限制模型调用数、候选数、证据字节和输出 Token。超时返回已找到的证据与缺口，不能取消用户当前主任务。continuation 只复用同作用域、同问题和未过期的候选。

### 4.3.1 模型参与的分层检索

PR-06 的 memory.resolve 由独立记忆检索执行器承担，可配置一个本地模型或低成本付费模型。它与主 Agent 分离编排上下文，但不要求独立常驻进程。第一版按配置使用一个后端，不自动从本地切到付费服务。

执行器首先查 Active 摘要候选并读取有希望的条目；不足时查询 Archived；仍不足才搜索 Obelisk 并读取局部原始证据。模型负责判断内容是否回答问题、扩展关键词、选择候选、决定是否继续下探及识别冲突。每层尽量复用已付费生成的摘要，有足够证据就停止。

每层的候选搜索仍使用零额外 LLM 的基础索引。模型不是新的全量语义索引，也不参与每轮热点匹配。热点匹配是另一条路径：纯本地词法匹配，只读取已持久化的短摘要，1 秒内必须完成，不调用模型，也不在现场生成摘要。主 Agent 仍可直接调用 memory.search 和 memory.read 处理简单问题；需要多步历史探索时才调用 memory.resolve。

Obelisk 路径采用“检索即形成记忆”的闭环。

1. 读取足够的局部原始证据，识别讨论范围、结论与冲突。
2. LLM 生成符合要求的中期摘要，保留来源；它就是本次返回给主 Agent 的历史总结，不再另生成一份平行总结。
3. 原子保存该摘要、来源及待生成短摘要任务，返回同一正文、URI、revision 和实际保存状态。
4. 基于该中期摘要二次生成短摘要，更新关键词和别名，按容量与近期热度规则评估入池。完成短摘要不意味着绕过容量强制入池，也不触发本 Session 重复注入。

只有本次取得有效证据的 Obelisk 路径强制执行该流程。已有 Active 或 Archived 摘要足够时直接复用，不重复提炼。无结果不保存空记忆，证据不足以满足摘要要求时如实返回 partial。存在有效但冲突的证据时可生成明确记录分歧的摘要，不能伪造统一结论。幂等键识别同一请求或同一来源版本的重试，复用已经保存的摘要，不重复创建记录。

中期摘要生成与持久化进入本次请求关键路径，约 30 秒的热路径预算必须给它们预留空间，不能把全部预算耗在搜索上。冷检索的超时单独记账，不挤占成文预算。短摘要生成可用已持久化任务继续执行，失败只重试第二阶段。写盘失败时可返回已生成摘要，但必须标记保存失败和可恢复状态，不得声称记忆已保存、热点已更新。

检索、摘要生成、持久化和短摘要更新分别记录耗时与费用。后端可以独立配置，外发证据仍遵守数据边界；不增加复杂自动模型路由。

### 4.4 pi 接入

- session_start 仅初始化配置、项目、本地热点索引和已注入记录，不注入词表。
- input 事件读取真实用户输入并匹配热点，排除 extension 自发消息，覆盖交互和 RPC 输入。
- 在最终交付给模型的本次用户输入末尾附加记忆块。input transform 是候选实现，但它发生在 skill 和模板展开之前，必须验证展开、排队及 steer 场景中的尾部位置。
- 若需要在最终消息组装阶段附加，仍与本次用户输入绑定，不能退回 system prompt 或启动额外 Agent 轮次。具体钩子通过 PR-05 的真实原型确定。
- 固定工具说明保留主动查询规则。动态热点词和短摘要不进入 system prompt。
- Session 继续、切换、分叉、回退和压缩维护对应的去重记录。交付失败不记为已注入，重复回调不产生重复块。
- 扩展关闭或搜索失败时主会话继续，工具明确返回不可用状态。

现有 Obelisk skill 与新工具会有职责重叠。新工具负责常规召回，旧 skill 保留人工诊断用途；试用时记录重复搜索和提示冲突。

探针实测见 [obelisk-adapter-findings.md](probes/obelisk-adapter-findings.md)。本机 0.3.0 会静默忽略 `projectPath`、`snippetTokens` 与 `contextLimit`，而 `project` 和 `cwd` 走 SQL `LIKE`，`-tmp-x_a` 会命中 `-tmp-x-a`。因此固定 **`@obelisk-apps/cli@0.3.2`**（npm latest）：它按 `project_path` 精确等值匹配，并对 `contextLimit > 6` 报错。0.3.2 现在既是本包依赖，也是本机全局版本，两者同为基线。不得先全库取 Top K 再在客户端过滤项目。

共享索引的兼容性已实测关闭这一风险。本机全局已升级到 0.3.2，与包内依赖同版本，不再存在两版并存。源码层面只读路径不迁移：`openReadDb()` 以 `readOnly: true` 打开数据库并只设 `busy_timeout`，`schema-migrations.js` 的 15 个 `COLUMN_MIGRATIONS` 只在 `openDb()` 和 `openAttuneDb()` 里以 `ALTER TABLE ... ADD COLUMN` 追加。真实索引已含全部 15 列（`sessions` 11、`memories` 11、`messages` 19），`coreSchemaNeedsMigration()` 返回 false，不会触发任何迁移。0.3.2 在真实索引上执行 `--search "vestigio" --limit 2` 退出 0 并返回正常消息体，前后列数不变。冷跑一次 59.9 秒，因为要刷新增量索引。构建时 stderr 会打印几十行 `Warning: skipped pi artifact ...: Unsupported or malformed Pi session header`，来源是 pi 写在会话目录里的 `observation-pack/ledger.jsonl`。因此适配器只看退出码与 stdout 的 JSON 判定成败，stderr 非空不算失败。

适配契约按实测锁定。`search` 和 `query` 都会触发 `refreshQueryIndex`，这是该工具的常规行为；但 `--query` 每次固定多付约 4 秒 invocation nonce 轮询，只有 `--search` 不需要，所以常规检索走 `--search`。`messages()` 是同步的，窗口上限 500，`relation:'parents'` 需要 `afterCount:0`。隐藏记录在任何情况下都不返回，`includeInactive` 只影响非隐藏的非活动行。消息 UUID 在重建、移动和改名后稳定，但会话文件前置插入会重排行号并改变 UUID，因此 `SourceRef` 必须靠 `content_hash` 与 `locator` 复核，不能只靠行号。

已知边界：真实索引上的冷检索约 19 秒（PR-01 基线实测，含索引刷新），本机约 6.97 GiB。热缓存的 fixture 与 10k 消息合成语料在 0.2 至 0.3 秒量级，二者不可互相外推。

Obelisk 源码声明 AGPL-3.0-only。发布前记录依赖方式与许可证要求。暂不复制其源码，也不将其私有内部模块作为稳定依赖。

输入追加只能用 `input` 回调的 `transform`。`before_agent_start` 无法改写用户输入，它只能替换 system prompt 或插入一条独立消息，两条都不可用。实测（见 [pi-input-findings.md](probes/pi-input-findings.md)）确认改写后的文本就是同一条用户消息的正文，追加位于该消息文本块的末尾，system prompt 逐字节不变。

已确认的限制是 `input` 回调在 skill 与模板展开之前触发，因此以 `/` 开头的输入不能安全追加。无参数的 skill 命令后直接接换行会被解析成 skill 名称的一部分，skill 正文丢失；模板调用的追加内容会被当作模板参数吃掉，或者泄漏进模板正文。扩展命令不触发 `input`。第一版只对普通用户文本追加，slash 命令输入记为未注入并保留原因，绝不改写命令语义；是否为命令由宿主声明（`host_command`），核心不猜测宿主约定。处理函数抛错时 pi 会捕获并放行原始输入，所以追加必须整体成功或整体放弃。

探针用本地 mock 服务器捕获了真实请求体，尚未跑真实 provider 的端到端验证。

PR-05 形成第一个试用闭环。可手动导入符合两级摘要约束的带来源记忆，验证提醒、查询和三层读取。自动深度检索与自动提炼尚未完成。

首次生成的中期摘要成功交付主 Agent 时，也按既有口径记录一次 access 并更新 last_access_at；保存和后台生成不计访问，重试交付按事件 ID 去重。

校验通过的中期摘要及来源可独立提交并读取，同时持久化待生成短摘要任务。短摘要失败不阻塞已保存中期摘要的返回，只重试第二阶段；导航就绪前该版本不进入热点。更新已有记忆时暂停失配导航，不能用旧导航指向新正文。

中期长度暂按正文非空白 Unicode 字符数计，范围包含 500 和 1000。短摘要按完整导航文本的 Unicode 字符总数计，包含标点与空白，上限包含 200。来源列表、标题、URI 与读取语法不计入摘要正文，但计入注入总预算。证据不足以写满 500 字时如实返回不足，不能以推测填充。

明确要求保存的用户输入仍保留直接来源。实现 checkpoint、租约和恢复，暂不做复杂跨记忆合并。幂等去重不要求每次下探都新建一条；已有同一来源版本的合格摘要时复用，发现新事实或冲突时保留更新依据。

PR-07 实测后确定的实现口径（结构不变，只调整数值与状态名）：

- 模型调用：检索判断仍最多 3 次（`RESOLVE_MAX_MODEL_CALLS`），中期成文单独预留 1 次（`RESOLVE_SUMMARY_MODEL_CALLS = 1`），因为 §10 明确要求为 PR-07 的强制总结预留预算；短摘要走后台任务，不计入请求内调用数。
- 输出 Token：判断单次上限调为 2000，成文单次上限 4000，请求累计上限调为 12000（= 4 × 2000 + 4000：三次判断、一次「答案读不出来」的重试，再加成文，让任一段都能用满自己的单次上限）。判断提示词要求答案不超过 300 字符，只说问题要的事实，不写开场白、不复述候选项；上限高于提示词目标，是给「正文前的推理」留位置。实测配置后端 `auto/deepseek-v4.1-flash` 在吐出正文前会先消耗约 1900 个推理 Token：判断上限 1200 时 82 次回复里 7 次被截断（每次 `tokens_out` 都等于 1200，JSON 断在半截），成文 1200/2500 会让 500–1000 字正文被截断（`medium_invalid:model_malformed_output:no_body`）或直接 502（“whole output spent on reasoning”）；加上 300 字符的短答案要求后，上限 1800 与 2400 各 20 次采样均无截断，实际用量最高 1294。输入 20000 Token、证据 24 KB/6 条、30 秒热路径与 120 秒冷检索上限不变。
- 持久化状态：新增 `insufficient_evidence`（证据不足 500 字，返回较短正文但不建记忆）与 `budget_exhausted`（`missing` 带缺口原因），`failed` 覆盖写盘与模型失败；四个阶段 `searched → summarized → saved → returned` 随结果返回。
- 写盘与任务同一事务：迁移 `0002_summary_jobs.sql` 新增 `summary_jobs`（唯一 `(memory_id, revision)`，租约与尝试次数）、`resolve_versions`（记录证据版本的去重与阶段）和 `usage_events(dedup_key)` 索引；保存记忆、入队短摘要任务、登记证据版本在 `saveMemory` 的同一 `beforeCommit` 内完成。
- 触发条件只看来源：仅当结论“resolved”且至少一条证据来自本次下探的历史摘录锚点（不按 provider 名判断，实际适配器报 `pi`）。只命中 Active/Archived 属于复用，不写摘要。
- 证据版本键：按 `provider/source_instance/session_id/message_id/content_hash` 排序取哈希；同键复用既有正文且不调用模型，不同键但标题主语冲突时在同一 URI 下递增 revision，导航置空。交付事件使用 `resolve-delivery:<request_id>:<memory_id>:<revision>` 去重，保存与后台生成不计访问。
- 证据体量闸门：证据少于 500 个非空白字符时直接返回 `insufficient_evidence`，不发起成文调用（实测 150 字证据曾被扩写成 826 字）；成文超过证据非空白字符数的 1.5 倍时判为 `failed`（`medium_longer_than_evidence`）。1.5 来自实测：忠实的中文正文约为原文的 1.3 倍，1.2 会把合格正文判死。
- 回放时效：`resolve_versions` 记录原答案，回放返回答案而不是标题；无显式 `request_id` 的问句键 10 分钟后不再回放，避免同一个短问题永久返回旧正文。

初始口径如下。“命中”的范围是本计划建议，尚未由使用者逐项确认。

- hit_count 在记忆通过作用域过滤、被热点匹配选中或作为搜索候选返回时增加。未进入候选的数据库行不计，事件保留热点和搜索 channel。
- 同一输入多个词和别名指向同记忆只计一次命中。后续用户输入再次命中可以增加计数，即使去重后没有再注入。提示去重和需求热度统计相互独立。

- last_access_at 取最近一次成功前台读取时间。未访问时为 null，不用创建时间代替。

高命中低访问可以是导航噪声，也可能表示无需再读，不能单独据此归档。长期低访问、低命中只作为候选信号，仍保留项目、固定保护和热点关联检查。先前讨论的 30 天只保留为中期归档实验参数，不用于短期热点过期，也不能单独触发闲置项目整体归档。归档命中不自动恢复，访问后更新统计并进入恢复评估。第一版不以读取冒充实际采用，也不强制反馈工具；真实采用可在评估中抽样核对。

维护由 harness 触发，不依赖 OS 定时任务，因此不带平台特性。候选触发点是会话开始、会话结束、压缩事件和显式命令。每次触发只做有界的一批任务，可中断可续跑，重复触发回到同一终态而不重复写入。pi 不常驻时不需要后台进程代劳，下次由 harness 触发的维护会补上未完成的批次。

## 15. 需要确认的产品选择

以下问题不能靠合成原型决定。技术细节由实现和实验处理。

1. **项目与全局范围。已定：项目级。** 默认只检索当前项目，显式全局偏好仍可在项目中查询，跨项目需显式扩大范围。
2. **外部模型的数据边界。已定：允许。** 后端为 `~/.pstack/models.md` 里的 deepseek 档（`magpie/auto/deepseek-v4.1-flash`，thinking low），单次、会话与每日预算见 PR-06 节。
3. **自动保存已明确。** LLM 通过 Obelisk 找到有效历史后，必须总结、返回并保存，继续更新短摘要。该路径无需再次确认权限；无结果或证据不足时不编造记忆。
4. **首轮历史样本。已定：`sprout-mio` 项目。** 用该项目已有的 pi 历史做验收语料，其他 provider 历史不进第一轮。
5. **去重边界。** 先按同一 Session、同记忆只注入一次。短摘要更新或压缩后能否再次提醒，仍待确定，默认不重注入。
6. **运行与维护。已定：由 harness 触发，不用定时任务。** 会话开始、会话结束、压缩事件和显式命令是触发点，每次只做有界批次，可中断可续跑，因此与操作系统无关。
7. **命中口径。** 计划暂同时记录热点匹配与搜索候选来源。是否只将热点匹配算命中，或分别用于排序，仍可调整。访问已明确为成功读取中期长摘要。

项目范围、模型数据边界、首轮样本和维护触发点已确认。Obelisk 成功检索后的自动保存已获明确授权。只剩去重边界与命中口径可按标明的建议试用调整，但不能擅自外发历史或扩大跨项目范围。

## 16. 本次采用的原则

- **Foundational Thinking** 使计划先固定 Memory、SourceRef、UsageEvent、两级摘要依赖和注入去重记录，再开始适配器与自动提炼。
- **Sequence work into verifiable units** 使每个 PR 都有独立结果、真实运行和性能账目，先交付 pi 查询闭环，再加入深度检索与维护。
- **Model the Domain** 使计划将热点成员关系、中期 Active 或 Archived 状态、进程内缓存分开，并用项目逻辑时钟表示使用机会，避免闲置时间被误算为失效。
- **Make Operations Idempotent** 使输入追加、命中与访问计数、分阶段提炼及归档都处理重复回调、重试和中断恢复。

这些原则的叶级说明已在本轮阅读。计划未将尚未运行的评估写成通过。
